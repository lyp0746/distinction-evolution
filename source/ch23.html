第23章　语言失败的六种方式

本章主张。这套语言会以六种方式失败：换词、过度统一、分级失效、路径依赖、不可通约、空域。每一种都有可检测的信号，并且都能在本书自己的章节里找到一次接近失手的记录。

六位医生会诊同一张片子，各自写下结论，六份结论互不相同。主任看完说：“你们不是看错了，是各自在用不同的片子。”

23.1　导论：失败要先分类，才能被检测

第 4 章给了五个“赝品”，那是针对“别人的统一”。本章是针对本书的：若这套语言在某个领域失败，它会长什么样？六种方式，六种信号。

23.2　换词与过度统一

换词。信号：把任何领域的名词换成“区分 + 阈值”之后，得不出新句子。本书的高危区是第 21 章的社会族（22、23、25、28 条都是 C 级）：把“制度”说成“区分动作的稳定性”，如果不给出一条可判定的准入规则，就只是换词。

过度统一。信号：同一个形式被套到符号差不同的对象上，却继续用同一套结论。第 14 章已经证明：形式定下、群就定下；符号差不同的形式不属于同一个几何。本书的高危区是把“五个领域同一个二次型”读成“五个领域同一个几何”。

23.3　分级失效与路径依赖

分级失效。信号：A 级结论被反复引用之后，B 级应用继承了它的语气。第 3 章的规矩（结论强度≤证据强度）挡的是单句，挡不住“一串引用”。对策是每条迁移都重标一次，而不是继承。

路径依赖。信号：先用某条构造得到结论，再用结论反过来论证构造的合理性。第 10 章的 1/3 就是例子：它在一个构造里可算，一旦被当成“结构的常数”，就变成了路径依赖的产物。

23.4　不可通约与空域

不可通约。信号：两套术语互相不可译，却声称被同一个框架覆盖。第 15 章的四个价位里，“类比”是允许的，“同构”要求双向翻译；把类比说成同构就是此处失败。

空域。信号：命题的前提在现实中几乎不成立（例如“预算无限紧”“所有耦合对称”）。第 16.5 节的有向图反例就是空域问题的镜像：定理只对无向图成立，若把它写成“一切网络”，前提就被悄悄改掉了。

23.4b　六种失败的自查顺序

按成本从低到高排一个自查顺序，读者可以在十分钟内跑完：（1） 换词查（换一个词，句子还成不成立）；（2） 空域查（前提在现实中成不成立）；（3） 分级查（有没有把 C 级的证据配 A 级的语气）；（4） 价位查（同调当同构）；（5） 路径依赖查（结论是不是只在这个构造里成立）；（6） 不可通约查（两套术语能否双向翻译）。

顺序的意义在于：前三条几乎不需要专业知识，后三条需要。若前三关就倒下，不必走到第四关——这也是本书把第 4 章的五个问题放在最前面的原因。

23.5b　六种失败 × 五个部分：一张诊断矩阵

把第 23.1—23.4 节的六种失败与本书五个部分交叉，可以得到一张“高危区”表。读法：格子里的数字是该部分最容易发生的失败编号。

这张矩阵本身就是结论：第五部分是最危险的部分（六种失败全在），第四部分最安全（只有路径依赖与空域两种）。它解释了为什么本书把“可复算”押在第四部分，而把第五部分写成“标级的覆盖”而不是“结论的推广”。

矩阵也给出一个使用建议：读第五部分时，每遇到一条 C 级，先查它落在哪一格。落在“换词”格的，要求一个能说出新话的句子；落在“空域”格的，要求一个具体反例；落在“不可通约”格的，要求一条双向翻译规则。

23.5　反例：一次真实的失败复盘

把“曲率”写成“谱的一侧”，是一次真实发生过、也真实失败过的迁移。失败方式属于过度统一＋路径依赖：先用谱的形式重写了曲率，再用“重写成功”论证曲率就是谱。第 2.5 节给出它的确切损失：整体恒等式成立（曲率之和＝欧拉示性数），局部信息丢失（同谱不同图的度序列不同）。复盘的结论只有一句：压缩可以成功，定理可以失败；报账时要分开报。

23.6　本章小结

六种失败方式、六种信号、六处高危区。它们不构成对本书的否定，而是它的使用说明：每读到一个结论，先看它离这六种失败有多近。第 24 章把“怎么裁决”写成程序。

一句话带走：一套语言的可信度，取决于它的失败方式是否被写在其使用说明的第一页。

23.6b　失败的自查脚本

把六种失败写成可执行的检查项，能在写作时自查：

def audit(claim, context):
    # 1 换词：删掉新术语，句子还成立吗？
    if same_after_renaming(claim, context): return "换词"
    # 2 过度统一：被套的对象与原型符号差相同吗？
    if signature(claim) != signature(context.prototype): return "过度统一"
    # 3 分级失效：证据等级 >= 语气等级吗？
    if evidence(claim) < strength(claim): return "分级失效"
    # 4 路径依赖：换一个构造，结论还在吗？
    if not holds_in(other_construction(claim)): return "路径依赖"
    # 5 不可通约：能写出双向翻译吗？
    if not translatable(claim): return "不可通约"
    # 6 空域：前提在现实中成立吗？
    if not feasible(premise(claim)): return "空域"
    return "通过"

这段代码的前四行是“伪代码”，最后两行是真正可判的。诚实的说法是：六项里只有第 3 项能完全自动化（等级比较），其余五项需要人判断。把这一点写出来，比假装有一个全自动检查器更可靠。
